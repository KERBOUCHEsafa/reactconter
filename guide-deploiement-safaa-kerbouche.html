🚀 Mettre le site en ligne (Render + Netlify)

Sans Cloudinary — tu n'as pas d'upload de photo, pas besoin.

💬 Avant de commencer Ce guide suppose que tu as déjà fini et testé le guide final (guide-final-safaa-kerbouche.html) sur la branche master : comptes, panier qui ne s'efface plus, commandes qui marchent en local. Ici, on fait la même chose mais en ligne, pour que n'importe qui puisse visiter ton site depuis son téléphone.
💡 Le principe en une phrase Ton projet a deux moitiés qui ne vivent pas au même endroit : le serveur (backend/) va habiter chez Render, le site (reacconter/) va habiter chez Netlify. Les deux doivent connaître l'adresse l'un de l'autre pour se parler — c'est tout le fil de ce guide.

Étape 1 — Préparer le code

1.1 — Un script pour démarrer le serveur "pour de vrai"

Sur ton ordinateur, tu démarres ton serveur avec npm run dev (qui relance tout seul à chaque modification, pratique pour travailler). Mais en ligne, Render ne modifie jamais ton code : il a juste besoin d'une commande simple pour démarrer une fois. Il lui manque ce script.

Ouvre backend/package.json, Ctrl + A, colle, Ctrl + S.

backend/package.json
{
  "type": "module",
  "scripts": {
    "start": "node server.js",
    "dev": "nodemon server.js",
    "seed": "node seed.js"
  },
  "devDependencies": {
    "nodemon": "^3.1.14"
  },
  "dependencies": {
    "bcryptjs": "^3.0.3",
    "cors": "^2.8.6",
    "dotenv": "^17.4.2",
    "express": "^5.2.1",
    "google-auth-library": "^11.1.0",
    "jsonwebtoken": "^9.0.3",
    "mongoose": "^9.10.0"
  }
}
💡 "start": "node server.js" — à quoi ça sert ? Render lit toujours un script appelé start pour savoir comment allumer ton serveur. Sans lui, Render ne saurait pas quelle commande lancer et ton site resterait éternellement "en train de démarrer".

1.2 — Le fichier anti-404 pour Netlify

Ton site a plusieurs pages (/panier, /checkout...). En local ça marche très bien, mais une fois en ligne, si quelqu'un appuie sur F5 sur /panier ou colle ce lien directement dans son navigateur, Netlify va chercher un vrai dossier panier qui n'existe pas et afficher une erreur 404. Ce petit fichier dit à Netlify : "peu importe l'adresse demandée, renvoie toujours la page principale, et laisse React choisir quoi afficher".

Crée ce fichier : clic droit sur reacconter/public → New File → tape exactement _redirects (sans extension) → colle → Ctrl + S.

reacconter/public/_redirects
/*  /index.html  200

1.3 — Pousser ces deux petits changements

Terminal
git add backend/package.json
git add reacconter/public/_redirects
git commit -m "Préparer le déploiement : script start et _redirects"
git push origin master

Étape 2 — Compte MongoDB Atlas

Ta base de données tourne en local sur ton ordinateur pour l'instant (mongodb://localhost ou une URI Atlas déjà testée). En ligne, Render n'a pas accès à ton ordinateur : il a besoin d'une base accessible depuis Internet. Si tu as déjà un compte MongoDB Atlas (gratuit) avec ton URI de connexion, passe directement à l'étape 2.2.

2.1 — Créer le cluster (si tu n'en as pas déjà un)

  1. Va sur mongodb.com/cloud/atlas, crée un compte gratuit.
  2. Create a deployment → choisis M0 Free → laisse la région par défaut → Create.
  3. Crée un utilisateur de base de données (nom + mot de passe, note-les quelque part).

2.2 — Autoriser Render à se connecter

Dans Atlas, menu Network Access → Add IP Address → clique sur Allow Access from Anywhere (ça ajoute 0.0.0.0/0) → Confirm.

⚠️ Pourquoi "n'importe où" et pas juste l'IP de Render ? Render change l'adresse IP de ton serveur de temps en temps (ce n'est pas une adresse fixe). 0.0.0.0/0 veut dire "n'importe quelle IP peut essayer de se connecter" — ce n'est pas un problème de sécurité ici, car il faut quand même le bon utilisateur et le bon mot de passe pour entrer dans la base.

2.3 — Récupérer l'URI de connexion

Menu Database → bouton Connect sur ton cluster → Drivers → copie l'adresse qui ressemble à :

mongodb+srv://UTILISATEUR:MOT_DE_PASSE@cluster0.xxxxx.mongodb.net/dzshop?retryWrites=true&w=majority

Remplace MOT_DE_PASSE par le vrai mot de passe de ton utilisateur (pas de < > autour). Garde cette ligne de côté, elle sert à l'étape 3.

Étape 3 — Mettre le serveur en ligne sur Render

  1. Va sur dashboard.render.com, connecte-toi avec GitHub.
  2. New → Web Service → choisis ton repo reactconter.
🎯 Le piège le plus fréquent : le Root Directory Ton repo a deux dossiers de code (backend/ et reacconter/). Si Render ne sait pas lequel utiliser, il va essayer de lancer le site React comme un serveur — et ça ne marchera jamais. Dans le champ Root Directory, mets exactement : 
backend

3.1 — Les variables d'environnement

Descends jusqu'à Environment Variables → Add Environment Variable, une par une :

CléValeur
MONGO_URIl'URI Atlas de l'étape 2.3
JWT_SECRETune longue phrase secrète, invente-la (ex: une phrase de 10 mots que tu es seule à connaître)
GOOGLE_CLIENT_IDton Client ID Google (celui du guide final, le même que dans ton .env local)
FRONTEND_URLlaisse http://localhost:5173 pour l'instant, on la corrigera à l'étape 5

Clique sur Create Web Service. Attends 2 à 5 minutes (regarde les logs qui défilent). Quand tu vois MongoDB connecté et Serveur sur..., c'est bon.

En haut de la page, copie l'adresse de ton service, qui ressemble à https://dzshop-safaa-api.onrender.com. Garde-la, tu en as besoin à l'étape 4.

  1. Va sur app.netlify.com, connecte-toi avec GitHub.
  2. Add new site → Import an existing project → choisis reactconter.

Avant de cliquer sur Deploy, déroule Advanced → New variable, deux variables :

Clique sur Deploy. Attends 1 à 3 minutes. À la fin, Netlify te donne une adresse du genre https://nom-au-hasard.netlify.app. Garde-la.

Étape 5 — Reconnecter les deux (CORS)

💡 Pourquoi revenir sur Render ? Ton serveur a une liste d'adresses autorisées à lui parler (le CORS, vu dans le guide final). Pour l'instant cette liste contient seulement localhost. Sans cette étape, ton vrai site en ligne sera bloqué par ton propre serveur avec une erreur CORS dans la console (F12).
  1. Retourne sur dashboard.render.com → ton service → Environment.
  2. Modifie FRONTEND_URL → mets ta vraie adresse Netlify de l'étape 4 (ex: https://nom-au-hasard.netlify.app, sans / à la fin).
  3. Save Changes → Render redémarre tout seul (1-2 minutes).

Étape 6 — Google Cloud : autoriser ta vraie adresse

Ton bouton "Connexion avec Google" a été autorisé pour localhost uniquement pendant les tests. Il faut ajouter ta vraie adresse.

  1. Va sur console.cloud.google.com/apis/credentials, ouvre ton identifiant OAuth (celui du guide final).
  2. Dans Authorized JavaScript origins, clique Add URI → colle ta vraie adresse Netlify (ex: https://nom-au-hasard.netlify.app, sans / à la fin).
  3. Save. Ça peut prendre quelques minutes pour s'appliquer.

Étape 7 — Vérifier et dépanner

Ouvre ta vraie adresse Netlify et vérifie, dans l'ordre :

  • ☐ La page d'accueil et le catalogue s'affichent (les produits viennent bien de ta base en ligne)
  • ☐ Inscription puis connexion marchent
  • ☐ Le bouton Google apparaît et connecte
  • ☐ Ajouter au panier, recharger la page (F5) → le panier est toujours là
  • ☐ Passer une commande → elle apparaît bien, et le stock du produit a baissé
  • ☐ Recharger directement sur /panier ou /checkout (coller l'adresse) → pas d'erreur 404
